Do AstrBot até a extensão

Esta página segue o código-fonte. Os links apontam para commits fixos: AstrBot 831abae e host 2d2f261.

1. O AstrBot carrega o plugin

PassoO que aconteceCódigo
Descobrir O AstrBot percorre o diretório de plugins. Um subdiretório vale como plugin quando tem main.py ou <nome>.py. _get_modules
Ler os metadados O AstrBot lê metadata.yaml. O arquivo dá o nome, a versão e a versão mínima do AstrBot. _load_plugin_metadata
Importar O AstrBot instala requirements.txt, lê _conf_schema.json e importa o módulo. A classe Star do plugin entra no registro. load

2. O host carrega a extensão

O AstrBot termina o trabalho no passo anterior. O host faz o resto dentro do próprio plugin.

PassoO que aconteceCódigo
Procurar O host lê extensions.enabled_ids. Para cada id, o host procura <raiz>/<id>/extension.yaml nas duas raízes: extensions/ do plugin e extensions/ do diretório de dados. load_all
Validar O id deve ser igual ao nome do diretório. O api_version deve ser 1. A versão do host deve atender min_host_version. load_manifest
Importar O host importa o pacote com o nome privado _dw_ext_<id> e chama setup(api). Uma falha coloca só essa extensão no estado de erro e remove os registros dela. _load_one
Registrar setup(api) registra o presenter, as fontes e os pollers. register_poller exige a permissão network e aplica o intervalo mínimo de 60 s. register_poller
Rodar O host cria uma tarefa por poller, com uma sessão HTTP compartilhada. Cada evento segue para _handle_disaster_event. Uma falha aumenta a espera até 10 vezes o intervalo. _run_poller

O que cada extensão registra

ExtensãoFontesPollers com a configuração padrão
br_south_disaster br_south_disaster_cemaden_alerts, br_south_disaster_cemaden_rain 1 de alertas e 3 de chuva, um por UF, a cada 300 s.
br_south_waterq br_south_waterq_balneabilidade 3, um por UF, a cada 21600 s, com limite de 60 s por leitura.

Instalar à mão

O host ainda não tem um fluxo de instalação. Este exemplo instala as extensões no diretório de dados do plugin:

<dados do plugin>/extensions/
├── br_south_disaster/   # extension.yaml, __init__.py, extension.py, locale/
└── br_south_waterq/

Depois, o operador preenche extensions.enabled_ids e recarrega o plugin. A próxima página mostra a configuração.

A extensão roda como código Python no mesmo processo do host. O host isola uma falha de carga, mas não limita o que a extensão pode fazer. A permissão network é uma declaração, não uma barreira.

E as páginas de plugin do AstrBot?

O AstrBot tem um recurso de páginas de plugin: views/<nome>/index.html dentro do plugin, com a ponte window.AstrBotPluginView e rotas de context.register_web_api. O host no commit fixo não tem views/ nem pages/. Uma extensão também não pode declarar uma página, porque o AstrBot só procura páginas no plugin. Uma tela de extensões precisa de uma mudança no host.
