O módulo comum das extensões

O código que as duas extensões repetem agora existe em Rust, no módulo piabrota_alerts.ext. Nenhuma extensão usa o módulo ainda.

Onde o código fica

  1. alerts-ext: a lógica pura em Rust, sem Python e sem rede. Um crate do alerts pode usar a lógica diretamente.
  2. alerts-py: expõe piabrota_alerts.ext com PyO3. Só esta camada toca objetos Python.
  3. Extensão: mantém setup(api), as fontes, o texto e os arquivos de locale/.

Como um poller fica

import piabrota_alerts.ext as c

async def read(session, url):
    async with session.get(url) as resp:
        resp.raise_for_status()
        return c.parse_feed(await resp.text(), list, url)

A extensão mantém o async with. O módulo não lê a rede. Um teste do autor mostrou o motivo: uma função em Rust que conduz a sessão do aiohttp pula o __aexit__ quando o asyncio cancela a tarefa. Depois de 3 cancelamentos, as 3 conexões do pool ficaram presas. Com o async with em Python, nenhuma conexão ficou presa.

Instalar

pip install "piabrota-alerts @ git+https://github.com/piabrota/alerts#subdirectory=crates/alerts-py"

O teste do autor levou 141 s em um contêiner python:3.12-slim e deixou 1,5 GB no cache, porque o maturin baixa o Rust quando o host não tem Rust. O comando também precisa de git e de um compilador C. A imagem do AstrBot tem os dois.

Um wheel evita esse custo. Um wheel abi3 tem 250 KB e serve para Python 3.10 ou mais novo. O teste do autor rodou o mesmo wheel de macOS arm64 em Python 3.10, 3.11, 3.12 e 3.13. O wheel de Linux aarch64 foi gerado e importado em Python 3.12. ⚠ Ninguém testou Linux x86_64 nem Windows.
